# Review, v2.1, 2026-11-24

**Reviewed by**: Staff Software Engineer (Review Subagent)  
**Scope**: 371 files (355 modified/added/deleted in branch v2.1 vs main, 16 untracked files)  
**Verdict**: Blocked  

## Summary
The branch introduces an ambitious, feature-rich upgrade delivering the v2.2 decoupled S3 + SQS durable extraction pipeline, deterministic candidate identity resolution, and strict fairness scoring compliant with the v2 scoring policy. While core algorithms and end-to-end integration tests (164 backend tests, 24 frontend Playwright specs) pass consistently, critical security vulnerabilities (cross-tenant IDOR, missing endpoint authorization), data-loss race conditions in recruiter decision state, and architectural divergence between design specifications (orphaned outbox pattern, dual data models) must be addressed before this branch can safely merge to `main`.

## Blockers
### 🔴 Cross-Tenant IDOR and Session Ownership Bypass, `backend/src/api/routes/jobs_v2.py:148-166`
**Problem**: In `enforce_session_ownership()`, the tenant isolation check specifies `if ctx and ctx.org_id and ctx.org_id != "org_default" and job_org and job_org != "org_default": if ctx.org_id != job_org: raise 403`. When a job belongs to `org_default` (or has null `org_id`), this check is entirely skipped for users of other organizations (`job_org != "org_default"` is False). Furthermore, the fallback session check `if job_session and caller_session and job_session != caller_session: raise 403` only evaluates when `caller_session` is truthy; if a caller omits the session cookie/header, `caller_session` is `None`, and the check silently succeeds.
**Why it matters**: Any authenticated user from a newly registered tenant who omits session headers can access, analyze, mutate, download resumes from, or delete jobs belonging to `org_default`. This is a direct cross-tenant IDOR vulnerability that violates tenant isolation.
**Suggested fix**: Enforce tenant boundaries strictly using `enforce_tenant_ownership()` unconditionally on every job route before session checks. Fail closed if `job.session_id` is present but the caller does not supply a valid matching session credential.

### 🔴 Missing Authorization on Extraction Metrics Endpoint, `backend/src/api/routes/jobs_v2.py:1914-1925`
**Problem**: The route `GET /api/v2/jobs/{job_id}/extraction-metrics` validates authentication via `Depends(get_auth_context)`, but completely omits both `enforce_session_ownership()` and `enforce_tenant_ownership()`.
**Why it matters**: Any authenticated user across any organization (or an unauthenticated caller in development environments) can query this endpoint for any arbitrary `job_id` and enumerate all candidate names, document IDs, original filenames, extraction timings, and identity statuses.
**Suggested fix**: Add `enforce_tenant_ownership(getattr(job, "org_id", "org_default"), ctx)` and `enforce_session_ownership(job, request, ctx)` immediately after retrieving the `JobItem` in `get_extraction_metrics()`.

### 🔴 Unsynchronized S3 JSON Read-Modify-Write Race Condition in Recruiter Decisions, `backend/src/api/routes/jobs_v2.py:1796-1834`
**Problem**: `update_candidate_decision()` handles recruiter decisions (shortlisting, rejecting, adding notes/reasons) by performing an uncoordinated read of `jobs/{job_id}/results.json` from S3, mutating the candidate in Python memory, and issuing a raw `put_object()` back to S3.
**Why it matters**: There is no optimistic locking (ETag / `If-Match`), DynamoDB transaction, or distributed lock. When two recruiters review candidates concurrently, or when a recruiter records a decision while `FinalRankWorker` writes updated rankings, the second write silently overwrites and destroys the first recruiter's decisions and notes. This violates the core project concurrency requirement that mutations must be atomic and idempotent.
**Suggested fix**: Persist recruiter candidate decisions, notes, and rejection reasons as first-class entity records in DynamoDB (`PK=JOB#{job_id}`, `SK=DECISION#{document_id}` or attributes on `DOC#{document_id}`) with optimistic locking via version numbers, and merge them into ranking responses at read-time rather than mutating a shared monolithic JSON blob in S3.

## Major
### 🟠 Orphaned Transactional Outbox Pattern, `backend/src/infrastructure/queue/queue_manager.py:68, 144, 164` vs `backend/src/infrastructure/queue/outbox.py:40`
**Problem**: `docs/v2.2/DURABLE_PIPELINE_AND_QUEUE_DESIGN.md` §4.4 states that all pipeline stage transitions use the transactional outbox pattern via `write_outbox_and_send()` to prevent message loss on server crashes. However, inspection reveals that `write_outbox_and_send()` is never invoked anywhere in the codebase. All enqueue functions (`enqueue_fast_parse`, `enqueue_odl_batch`, `enqueue_nova`, `enqueue_final_rank`) bypass the outbox and call `adapter.send_message()` directly, while `BackgroundWorkerDaemon` runs an outbox relay worker every 30 seconds that queries an empty table.
**Why it matters**: If a server or worker crashes immediately after updating a DynamoDB state (e.g. `sessions_repo.update_status(..., FINAL_RANKING)`) but before `adapter.send_message()` completes, the session is left permanently stuck in an intermediate state with no message in SQS and no outbox record to replay.
**Suggested fix**: Route all queue publishing through `write_outbox_and_send()` as documented in §4.4, or update the architecture design doc to accurately reflect synchronous direct SQS publishing with explicit compensating timeout recovery.

### 🟠 Broken Extraction Telemetry Due to Legacy Status Enum Check, `backend/src/api/routes/jobs_v2.py:1928-1930`
**Problem**: In `get_extraction_metrics()`, extracted and failed documents are filtered via `d.status == DocumentStatus.PARSED` and `d.status == DocumentStatus.PARSE_FAILED`. In the v2.2 durable pipeline, documents transition to terminal statuses `STRUCTURED_PARSED` or `REVIEW_REQUIRED`.
**Why it matters**: The list comprehension `extracted` evaluates to an empty list `[]` for all v2.2 sessions. Consequently, `avg_quality_score` always reports 0.0, identity metrics are completely zeroed, and per-document extraction telemetry is never returned for v2.2 workloads.
**Suggested fix**: Update the status checks in `get_extraction_metrics()` to match v2.2 document states: `d.status in (DocumentStatus.STRUCTURED_PARSED, DocumentStatus.REVIEW_REQUIRED, DocumentStatus.SCORED)`.

### 🟠 Infinite SSE Loop and Resource Leak on Failed Jobs, `backend/src/api/routes/jobs_v2.py:1443-1471`
**Problem**: In `extract_resumes_stream()`, when documents exist for a job, `is_terminal_job` only tests `JobStatus.READY, READY_WITH_WARNINGS, DONE, DONE_WITH_ERRORS`. It does not include `JobStatus.FAILED`. If a job transitions to `FAILED`, `is_terminal_job` remains `False`, and lines 1471-1472 (`await asyncio.sleep(0.5); continue`) continuously loop without ever reaching the outer `elif job.status == JobStatus.FAILED` handler.
**Why it matters**: When a job with documents fails, connected SSE streams remain open indefinitely, querying DynamoDB twice per second in a tight loop until the client forcibly disconnects, causing unnecessary CPU and database consumption.
**Suggested fix**: Check `job.status == JobStatus.FAILED` inside the `if docs:` branch, emit `event: error`, and break the generator loop.

### 🟠 Insecure Default and Fail-Open Authentication, `backend/src/api/dependencies/auth.py:63-74`
**Problem**: When `STRICT_AUTH` is not set to `true` and `ENVIRONMENT` is not `prod`/`production` (the default in `.env.example`), `get_auth_context()` catches invalid or missing tokens and returns `get_default_auth_context()`, silently elevating unauthenticated callers to recruiter privileges in `org_default`.
**Why it matters**: Deployments that fail to explicitly configure `ENVIRONMENT=prod` or `STRICT_AUTH=true` run completely unauthenticated in production, violating the core security rule that authn/authz must fail closed.
**Suggested fix**: Default `STRICT_AUTH` to `true` whenever running outside automated local unit test fixtures, or require an explicit development override flag (e.g. `ALLOW_DEV_ANONYMOUS_AUTH=true`) rather than failing open by default.

### 🟠 In-Memory User and Organization Registry, `backend/src/api/auth.py:76-98, 163-186`
**Problem**: User and organization accounts created via `POST /api/v2/auth/register` are stored in process-local dictionaries `_USERS` and `_ORGANIZATIONS`.
**Why it matters**: Multi-worker uvicorn setups or containerized deployments cannot share user accounts across processes (a user registered in worker A cannot log into worker B), and all registered users are wiped out upon process restart.
**Suggested fix**: Persist user and organization entities in DynamoDB using dedicated partition keys (`USER#{email}`, `ORG#{org_id}`) with salt and password hashes stored durably.

### 🟠 Static Shared Salt in Password Hashing, `backend/src/api/auth.py:84-86`
**Problem**: `_hash_password()` uses a static, hardcoded salt `salt = b"sortlist_v2_salt"` for all users across all organizations.
**Why it matters**: Identical passwords generate identical hashes, rendering user credentials vulnerable to precomputed rainbow table attacks.
**Suggested fix**: Generate a cryptographically secure random salt (e.g. `os.urandom(16)`) per user upon registration and persist the salt alongside the password hash.

### 🟠 God Route File and Layering Violations, `backend/src/api/routes/jobs_v2.py:1-1997` & `backend/src/infrastructure/repositories/jobs_repository.py:185-300`
**Problem**: `jobs_v2.py` has grown to 1,997 lines (exceeding the AGENTS.md guideline of <= 300 lines by over 6x). Route handlers directly execute DynamoDB queries, outbox reconciliations, queue messaging, and S3 file modifications. Concurrently, `JobsRepository.request_analysis()` imports other repositories, coordinates outbox writes, checks terminal barriers, and dispatches SQS queue events inside a database repository class.
**Why it matters**: Violates clean separation of concerns: routes should only parse/validate requests and shape responses; repositories should only perform database CRUD; services should own business workflows. This makes debugging, testing, and future maintenance error-prone.
**Suggested fix**: Extract business logic into an `AnalysisService` and `UploadSessionService`. Keep `jobs_v2.py` as thin HTTP delegates, and remove queue dispatch logic from `JobsRepository`.

### 🟠 Dual Data Model and Repository Desynchronization, `backend/src/api/routes/jobs_v2.py:1044-1063, 1754-1768`
**Problem**: The codebase maintains two separate DynamoDB item types for each resume: `DocumentItem` (`DOC#{document_id}`) managed by `DocumentsRepository` and `FileItem` (`FILE#{file_id}`) managed by `FilesRepository`. Several routes mutate one model while leaving the other stale (e.g. `delete_resume` marks `FileItem` as `REMOVED` but leaves `DocumentItem` untouched).
**Why it matters**: Divergent states between `DocumentsRepository` and `FilesRepository` cause subtle race conditions and display glitches depending on which repository an endpoint reads from.
**Suggested fix**: Consolidate resume tracking into a single canonical entity model (`DocumentItem`) and deprecate `FileItem` and `FilesRepository`.

### 🟠 Frontend ESLint Compilation and Effect Violations, `frontend/src/components/job-setup/AnalyzeButton.tsx:210, 344` & `frontend/src/components/detail/CandidateActions.tsx:42`
**Problem**: Running `npm run lint` fails with 17 errors:
1. In `AnalyzeButton.tsx`, `monitorAnalysisProgress` (line 210) and `handleClick` (line 344) are referenced inside their own `useCallback` hook bodies before lexical declaration, triggering compiler errors.
2. In `CandidateActions.tsx:42`, `setNoteInput` is called synchronously inside `useEffect`, violating React 19 rules and triggering cascading re-renders.
**Why it matters**: Linter failures block CI pipelines and indicate potential temporal dead zone (TDZ) and re-render performance defects in production.
**Suggested fix**: In `AnalyzeButton.tsx`, use callback refs (following the pattern established in `BackendHealthGate.tsx`) to avoid self-referential closures before declaration. In `CandidateActions.tsx`, initialize `noteInput` state from props or synchronize via controlled event handlers instead of synchronous effect-driven `setState`.

## Minor
### 🟡 Client IP Spoofing & Monotonic Memory Leak in Rate Limiter, `backend/src/api/middleware/rate_limit.py:44-48, 67-104`
**Problem**: `_get_client_key()` blindly trusts `X-Forwarded-For.split(",")[0]`, allowing clients to bypass IP rate limits by sending arbitrary headers. Additionally, empty client timestamp arrays in `self._history` are never deleted, leaking memory monotonically.
**Why it matters**: Rate limits on `/ats-check` and `/auth/login` can be trivially evaded, and the server process will slowly leak memory under diverse traffic.
**Suggested fix**: Only trust `X-Forwarded-For` from verified reverse proxies, and delete keys from `self._history` when their timestamp list becomes empty.

### 🟡 CSV Formula Injection Risk, `backend/src/api/routes/jobs_v2.py:1889-1904`
**Problem**: In `export_job_csv()`, candidate names, notes, and rejection reasons are output directly into CSV cells without escaping formula trigger characters (`=`, `+`, `-`, `@`).
**Why it matters**: If a candidate resume or recruiter note contains malicious formula syntax, spreadsheet applications like Excel may execute arbitrary commands when an exported CSV is opened.
**Suggested fix**: Sanitize all text fields in CSV exports by prefixing values starting with `=`, `+`, `-`, or `@` with a single quote (`'`).

### 🟡 HTTP Header Injection / Response Splitting Risk in Resume Download, `backend/src/api/routes/jobs_v2.py:1695`
**Problem**: `download_resume()` interpolates raw `filename` directly into the `Content-Disposition` header: `f'inline; filename="{filename}"'`.
**Why it matters**: Filenames containing unescaped double quotes, carriage returns (`\r`), or newlines (`\n`) can corrupt response headers or enable HTTP response splitting.
**Suggested fix**: Sanitize or URL-encode the filename in `Content-Disposition` headers (e.g. using `urllib.parse.quote()`).

### 🟡 Unbounded Presigned PUT Upload Payload Size, `backend/src/infrastructure/storage/storage_service.py:59-76`
**Problem**: `generate_presigned_put_url()` generates direct S3 PUT URLs that do not enforce a maximum payload size. While the backend verifies size later during `complete_document_upload()`, a malicious or misconfigured client can upload hundreds of megabytes directly into S3 before rejection.
**Why it matters**: Wasted S3 storage and bandwidth costs from unvalidated large uploads.
**Suggested fix**: Migrate direct S3 uploads to `generate_presigned_post()`, which strictly enforces `["content-length-range", 1, 10485760]` at the S3 boundary.

### 🟡 O(N) Serial DynamoDB Writes on Session Creation, `backend/src/api/routes/jobs_v2.py:939`
**Problem**: `create_upload_session()` loops over up to 100 files and calls `_docs_repo.create(doc_item)` sequentially for each file.
**Why it matters**: 100 consecutive synchronous round-trips to DynamoDB add 500ms–2000ms latency to the session initialization endpoint.
**Suggested fix**: Use `_table.batch_writer()` to write `DocumentItem` records in batches of 25.

### 🟡 Session Token in URL Query Parameters, `backend/src/api/dependencies/auth.py:47-48`
**Problem**: `get_auth_context()` accepts session tokens passed via `request.query_params["token"]`.
**Why it matters**: Tokens in query parameters are captured in server access logs, browser history, and Referer headers.
**Suggested fix**: Restrict session credentials to httpOnly cookies and `Authorization: Bearer` headers.

## Strengths
- **Rigorous Identity Resolution**: `CandidateIdentityResolver` cleanly replaces the fragile first-match heuristics with multi-signal arbitration, spatial weighting, and contact adjacency rules. Table-driven test coverage explicitly prevents regression on the `"Insights possible sub-space."` false-positive defect.
- **Fairness Policy Adherence**: The candidate scoring engine strictly complies with `SCORING-POLICY.md`, disabling FAANG/employer prestige lists, university prestige bonuses, and career gap penalties. Sub-scores and factor ledgers are preserved for knocked-out candidates rather than zeroed out.
- **Decoupled Architecture & SQS Decoupling**: Presigned S3 uploads combined with lightweight Range-request magic-byte validation (HTTP 202) completely eliminate the legacy HTTP 429 rate limit issues on bulk uploads.
- **Resilient Fallback Handling**: `NovaService` incorporates robust Pydantic structured output validation, JSON markdown unwrapping, and mock-aware throttling protections for Bedrock LLM fallbacks.
- **Comprehensive Verification Signal**: 164 backend integration/unit tests pass with 0 failures, and 24 Playwright frontend E2E specs pass across ranking, analyze lifecycle, fault injection, and state recovery.
